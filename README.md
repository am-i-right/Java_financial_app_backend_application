# Личные финансы — учебный проект на Java

[![Java CI](https://github.com/am-i-right/Java_financial_app_backend_application/actions/workflows/ci.yml/badge.svg)](https://github.com/am-i-right/Java_financial_app_backend_application/actions/workflows/ci.yml)

Консольное приложение для практики ООП: несколько пользователей, личные кошельки,
доходы и расходы, категории, месячные бюджеты и текстовые отчёты.
Все данные хранятся **только в памяти** и теряются при завершении процесса.

Проект использует Java 17 и стандартную библиотеку. Единственная зависимость —
JUnit 5 для тестов. Spring, база данных, веб-сервер, Lombok и Mockito не нужны.

## Сборка и запуск

Требуются **JDK 17 или новее** (именно JDK, не только JRE), **Maven 3.9+** и
терминал с UTF-8. При первой сборке нужен интернет для загрузки Maven-плагинов и JUnit.

```bash
git clone https://github.com/am-i-right/Java_financial_app_backend_application.git
cd Java_financial_app_backend_application
java -version
mvn -version
mvn clean verify
java -jar target/finance-app.jar
```

В IntelliJ IDEA откройте `pom.xml` как Maven-проект, выберите JDK 17+ и запустите
`com.myfinance.Main`. Если кириллица отображается неверно, установите UTF-8
для консоли и файлов проекта.

Проверить готовый пример без ручного ввода (Bash или Windows cmd):

```bash
java -jar target/finance-app.jar < examples/demo-input.txt
```

Пример создаёт учебную учётную запись `demo` с паролем `demoPass123`, категории
«Зарплата» и «Еда», доход 1000 RUB и расход 120.50 RUB. При бюджете 100 RUB
появятся предупреждение о превышении на **20.50 RUB** и баланс **879.50 RUB**.
Это вымышленные данные; учётная запись не создаётся автоматически при обычном запуске.

## Как пользоваться

1. Зарегистрируйтесь, затем отдельно войдите по тому же логину и паролю.
2. Создайте категорию дохода, например «Зарплата», и категорию расхода «Еда».
3. Добавьте доход: категория, сумма, дата.
4. Установите бюджет для категории расходов: категория, месяц, лимит.
5. Добавьте расход. После операции приложение покажет актуальные предупреждения.
6. Посмотрите баланс, историю или отчёт за выбранный месяц.
7. Выйдите из аккаунта и зарегистрируйте другого пользователя для проверки изоляции.

После входа доступны команды:

| Команда | Действие |
| --- | --- |
| `1` | Создать категорию: тип `1` — доход, `2` — расход |
| `2` / `3` | Добавить доход / расход |
| `4` | Установить или изменить месячный бюджет |
| `5` | Показать баланс за всё время |
| `6` | История по дате, от ранних операций к поздним |
| `7` | Отчёт за месяц: доходы, расходы, категории, бюджеты |
| `8` | Список категорий |
| `9` | Выйти из аккаунта, сохранив данные в памяти процесса |
| `10` | История по абсолютной сумме, по возрастанию |
| `0` | Завершить приложение и потерять данные |

Дата вводится как `2026-11-09`, месяц — `2026-11`. Пустой ввод означает
сегодняшнюю дату или текущий месяц **по часовому поясу компьютера**.
Суммы принимаются с точкой или запятой, например `120.50` или `120,50`.
Все поля читаются построчно, поэтому названия категорий могут содержать пробелы.
При ошибке приложение возвращается в меню: команду нужно выбрать заново.
Конец ввода (EOF), включая прерванную команду, завершает программу без стека исключений.

## Правила и упрощения

- Один кошелёк на пользователя; в консоли одновременно активен один аккаунт.
- Логины чувствительны к регистру, внешние пробелы обрезаются. Повторный логин запрещён.
- Пароль содержит минимум 8 символов и не состоит целиком из пробелов.
  Регистр и пробелы пароля значимы. Ввод через `Scanner` **виден в консоли**.
  В `User` сохраняются только соль и PBKDF2-хеш, открытого пароля в полях нет.
- Названия категорий уникальны в пределах кошелька без учёта регистра и внешних пробелов.
  Тип категории задаётся при создании и не меняется. Доход нельзя добавить в категорию расходов.
- Одна валюта — RUB. Все суммы и лимиты строго положительные, точность — копейки.
  Лишние значащие дробные знаки отклоняются, а не округляются. `12.100` допустимо как `12.10`.
- Баланс равен сумме доходов минус сумма расходов **по всем записанным операциям**.
  Он вычисляется из истории, отдельного изменяемого поля баланса нет.
- Дата принадлежит операции, а не моменту ввода. Допустимы прошлые и будущие даты;
  все внесённые операции сразу участвуют в общем балансе. Отложенного исполнения нет.
- Бюджет задаётся для пары «категория расходов + календарный месяц».
  Он не переносится автоматически на следующий месяц; неиспользованный остаток тоже.
  Повторная установка заменяет только лимит выбранной пары. Бюджет можно задать после расходов.
- Достижение лимита в точности не считается превышением. Превышение вызывает
  предупреждение и не мешает сохранить расход. Категория без лимита также принимает расходы.
- Отрицательный общий баланс разрешён и сопровождается отдельным предупреждением.
  Расходы сравниваются с месячным лимитом категории, **а не с балансом кошелька**.
- Отчёт показывает суммы только за выбранный месяц и отдельно общий баланс за всё время.
  История хранится в порядке добавления; сортировки работают с копиями.

Это однопоточное учебное приложение с консольным интерфейсом. В объём реализации
не входят REST API, JWT, база данных, экспорт/импорт, переводы между пользователями,
редактирование и удаление операций. Объём определён доступным контекстом задания
и предложенной структурой с `Main`, который читает команды пользователя.

## Структура

```text
src/main/java/com/myfinance/
├── Main.java                     # Меню, ввод, вывод и обработка ошибок
├── model/
│   ├── User.java                 # Логин, хеш пароля, личный кошелёк
│   ├── Wallet.java               # Категории, операции, месячные лимиты
│   ├── Transaction.java          # Абстрактная неизменяемая операция
│   ├── Income.java               # Доход
│   ├── Expense.java              # Расход
│   ├── Category.java             # Название и тип категории
│   └── Money.java                # Единая проверка денежных сумм
└── service/
    ├── AuthService.java          # Регистрация, вход, выход, текущий пользователь
    ├── FinanceManager.java       # Действия с финансами текущего пользователя
    ├── Report.java               # Контракт генерации отчёта
    └── ReportGenerator.java      # Реализация текстового отчёта

src/test/java/com/myfinance/      # Модульные и консольные сценарии JUnit 5
.github/workflows/ci.yml          # Сборка и тесты на Java 17 и 21
examples/demo-input.txt           # Готовый ввод для демонстрации
docs/WALKTHROUGH.md               # Пояснения логики и порядок изучения
```

## Где используется ООП

| Приём | Пример и назначение |
| --- | --- |
| Инкапсуляция | Поля моделей закрыты; списки выдаются как неизменяемые снимки |
| Абстракция | `Transaction` содержит общие сумму, дату и категорию |
| Наследование | `Income` и `Expense` наследуют `Transaction` |
| Полиморфизм | `getSignedAmount()` позволяет кошельку складывать операции без проверки их типа |
| Композиция | `User` содержит свой `Wallet`; кошелёк содержит операции и категории |
| Интерфейс | `Report` задаёт контракт; `ReportGenerator` его реализует |
| Static nested class | `Transaction.DateComparator` сортирует по дате без связи с конкретной операцией |
| Inner class | `Wallet.Alert` проверяет данные своего кошелька и возвращает сообщения |
| Anonymous class | Одноразовый `Comparator<Transaction>` в `FinanceManager.getTransactionsByAmount()` |
| Вложенный record | `Wallet.BudgetStatus` передаёт неизменяемый результат расчёта бюджета |
| Enum | `Category.Type` ограничивает тип категории двумя значениями |

Анонимный класс здесь оставлен как учебный пример. В прикладном коде его можно
заменить на `Comparator.comparing(Transaction::getAmount)`.

## Тестирование и GitHub Actions

```bash
mvn test           # Только тесты
mvn clean verify   # Чистая сборка, тесты и исполняемый JAR
```

Тесты проверяют авторизацию, изоляцию пользователей, точные денежные расчёты,
ограничения сумм и категорий, месячные границы бюджетов (включая смену года),
порог предупреждений, сортировки, отчёты и ввод через консоль.
Для тестов используются фиксированные даты; отдельно проверяется ввод текущей даты.

Workflow [Java CI](https://github.com/am-i-right/Java_financial_app_backend_application/actions/workflows/ci.yml) запускается на каждый push,
pull request и вручную. Команда `mvn clean verify` выполняется отдельно на Java 17
и Java 21. При успешной сборке JAR доступен в артефакте `finance-app`,
результаты JUnit — в `test-results-java-17` и `test-results-java-21`.
Локальные XML-отчёты лежат в `target/surefire-reports/`.

Подробный разбор реализации: [docs/WALKTHROUGH.md](docs/WALKTHROUGH.md).
